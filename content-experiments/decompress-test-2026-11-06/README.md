# 不刻意寫短的改寫測試（2026-11-06）

## 為什麼做

Darren 讀了 Clark、Martin、Mahowald〈Why is AI-generated language so hard to understand?〉（arXiv 2610.29162，2026-10-21），發現 Claude 回覆時會刻意寫短。論文的發現是：AI 訓練時被推著「用最少的字塞最多資訊」，結果比人更常用幾種難讀的寫法。這次拿一篇已上線文章，測試不刻意寫短、改寫成好讀的版本，看看差在哪裡。

- 底稿：`before.md`，〈稚內住宿〉2026-11-06 的 `reader-preview.md`（11/05 標竿優化後的線上版）
- 改寫稿：`after.md`
- 比較：`compare.md`
- 只是測試，不上傳、不改 `content-production/`。

## 論文的五種寫法對到中文

| 論文 | 中文文章裡的樣子 | 改法 |
|---|---|---|
| 東西當主詞、做人的動作 | 「官網寫在官網訂最便宜」「平台上有頁面不一定能訂」 | 主詞換成人：旅館、讀者、你 |
| 少見的詞語搭配 | 「跨年的行程排不進這一家」「冬天排不進這一家」 | 用台灣人平常的講法：「這家跨年期間沒開」 |
| 主詞和動詞隔很遠 | 一長串修飾放在主詞前面 | 修飾拆成另一句，主詞和動詞放近 |
| 名詞疊在一起 | 「早班渡輪報到時間」「北防波堤穹頂」這種一串名詞 | 能拆就拆成「早班渡輪要幾點報到」；專有名詞照留 |
| 為了短刪掉關係詞 | 一句用逗號串好幾家旅館的距離，讀者要自己比 | 一句講一件事，把「所以」「因為」「如果」寫出來 |

另外加一條：**推論要把步驟寫出來**。線上版「早餐只有大約20分鐘」把步驟省掉了，結果漏算走路時間，算錯了也看不出來。

## 不變的事

- 數字、時間、條件、店名、表格、延伸資料、資料來源一個都不動，不加新事實。
- 照寫作 Skill `writing-guide.md`（特別是第17條 Darren 的語氣）與 `check-voice.mjs` 的禁用詞。
- 「所以」「不過」「而且」的每千字上限這次不管，只記錄結果。
