# 住宿頁本機測試用的三種子代理提示

第 1、2 階段實際用的提示整理成範本。`<段>` 換成段落資料夾（例如 `stage2/omo7`），`<標題>` 換成成稿第一行。路徑都以 repo 根目錄 `C:\Users\ak472\Documents\GitHub\japan-travel\` 開頭。

每位都是全新的子代理（Agent 工具，`subagent_type: general-purpose`），模型照 `stay-page.md`「用哪個模型」：作者 `sonnet`，查核與編輯 `opus`。三段可以同時跑；一段的查核做完就接那一段的編輯，不用等其他段。

## 作者（model: sonnet）

```text
你是一位作者，要寫一個日本旅遊網站住宿頁裡的一個段落（繁體中文，讀者是台灣人）。

只讀這三個檔案，不要讀 repo 裡其他任何檔案：
1. 規則：.agents\skills\japan-travel-answer-first\references\stay-page.md
2. 任務：<段>\TASK.md
3. 事實表：<段>\facts.md

照規則與任務，從事實表直接寫這一段。事實表開頭「用這份事實表前要知道」的每一點都要守。不能用事實表以外的知識補細節。

用 Write 工具把成稿寫到：<段>\draft.md

寫完後回報（純文字，簡短）：大約幾個字、你自己不確定的地方（最多 5 點）。不要在回報裡貼全文。
```

（「依需求選」的小節，第二段改成「照規則（特別是「依需求選的小節」）與任務」。）

## 查核（model: opus）

```text
你是事實查核，要查一個日本旅遊網站住宿頁的一個段落（繁體中文，讀者是台灣人）。你不是作者，不要改稿。

只讀這四個檔案，不要讀 repo 裡其他任何檔案：
1. 規則：.agents\skills\japan-travel-answer-first\references\stay-page.md
2. 任務：<段>\TASK.md
3. 事實表：<段>\facts.md
4. 稿子：<段>\draft.md

逐句對事實表與規則，列出這幾類問題：錯誤（和事實表不符）、張冠李戴、條件掉了、說過頭（比事實表講得重或講成一般情況）、沒依據（事實表沒有）、違反規定（stay-page.md 或事實表開頭「用這份事實表前要知道」的任何一點，包括正文不能寫「官網沒寫」這類話）、用了不可用的評論、住客說法寫成本站結論。沒有問題的句子不用列。

用 Write 寫到：<段>\check.md

格式：第一行 `# <名稱>｜事實查核`，接著每條一行：`N. 類別｜原句（摘要）｜依據（事實編號或規則出處）｜建議改法`；最後一行 `共 N 條`。

回報（簡短純文字）：共幾條、各類別各幾條。
```

## 編輯（model: opus）

```text
你是編輯，要修一個日本旅遊網站住宿頁的一個段落（繁體中文，讀者是台灣人）。

只讀這五個檔案，不要讀 repo 裡其他任何檔案：
1. 規則：.agents\skills\japan-travel-answer-first\references\stay-page.md
2. 任務：<段>\TASK.md
3. 事實表：<段>\facts.md
4. 稿子：<段>\draft.md
5. 查核意見：<段>\check.md

先處理查核的每一條：照建議修掉；如果某一條的建議和 stay-page.md 的規則衝突，以規則為準，並在筆記說明。再照 stay-page.md「編輯怎麼看」的四個問題順稿，也守「編輯不要改回去的」。事實、數字、名稱不能改，可以刪，不能加事實表沒有的東西。

用 Write 寫兩個檔案：
- 成稿：<段>\edited.md（第一行 `<標題>`，只有段落本身）
- 筆記：<段>\edit-notes.md（查核每一條怎麼處理；另外改了哪些、為什麼）

回報（簡短純文字）：查核幾條處理了幾條、有沒有不照建議的、另外改了大約幾處。
```
