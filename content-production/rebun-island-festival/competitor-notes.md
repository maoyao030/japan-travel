# 禮文島祭典：讀競品筆記（2026-11-24）

先講結論：台灣沒有專講禮文島祭典的文章。「禮文島祭典」「禮文島 煙火」「禮文島 海峽祭」這類查詢，WebSearch 排出來的幾乎都是日文頁（walkerplus、觀光協會、visit-hokkaido）或同名的關門海峽煙火，沒有繁中專文。所以下面讀的是最接近的兩類：北海道夏季祭典與花火整理（學這種頁的資訊順序），和台灣人寫的禮文島、利尻禮文攻略（看他們怎麼處理祭典與季節）。筆記只記順序與習慣，事實一律不拿。

## 2. 各篇的順序

**LIVE JAPAN（祭典整理）**
- 大標題 → 一段導言（北海道夏天短、當地人很珍惜）→ 編號目錄（15 項，依月份）→ 每項一個 H2（月份加活動名稱加所在市町村）→ 總結段落。
- 每項內部：活動來歷或特色一兩段 → 現場看點 → 官網連結 → 資訊清單（地址、日期、電話、時間、交通）。
- 沒有表格、沒有月曆，日期散在各項資訊清單裡，要逐段找。

**iwafu（花火整理）**
- 長標題 → 目錄（五個分區）→ 一段總述 → 一段列舉重點活動 → 正文依地區分段 → 全季總整理 → 作者介紹。
- 每區開頭先放活動卡片（活動名稱、活動時間、活動地點），再接正文。
- 正文每場的順序：日期時間 → 會場位置 → 看點 → 附帶活動或美食 → 交通（車站加步行、開車） → 天候應對 → 票價與座位規定。
- 沒有表格或月曆。

**Funliday（禮文島 10 大景點）**
- 導言（位置加別稱「花之浮島」、季節、美食，再預告本文範圍）→ 目錄 → 前往禮文島 → 景點 1 到 10 → FAQ（Q1 到 Q5）→ 商品推廣區塊。
- 花季只用概略時段，FAQ 裡才分「6、7 月花季」「6 到 8 月最推薦」「5 月與 9 月平季」「10 月到隔年 4 月不建議」。沒有祭典，沒有逐月月曆。

**痞客邦（跳島攻略）**
- 個人感想開場 → 為什麼夏天是旺季（順帶說淡季也能去）→ 船與飛機 → 島上交通 → 兩組範例行程 → 利尻島 → 禮文島 → 延伸資料。
- 體驗類項目依序寫名稱、內容、費用、限定期間、官網、地址電話。季節限定一定標出來。沒有祭典。

**JNTO 臺灣版**
- 簡介 → 別錯過 → 交通 → 景點 → 氣候 → 行程建議。氣候一段只說夏季是花季與旺季，沒有活動日期。

## 3. 開頭怎麼寫

- 祭典整理類：先講北海道夏天短，所以每個活動都辦得特別熱鬧，再一句說明這篇挑了哪些活動，最後才進正文。氣氛先行，沒有先回答讀者的問題。
- 花火整理類：先講整體感受，再用一句話把幾場重點活動串起來讓讀者一眼看到有哪些，最後交代涵蓋的時間範圍。這個「先列選項再細講」的開法最貼近「一年有哪些祭典」這個問題。
- 禮文島攻略類：先定位（日本最北的離島、花之浮島），再講季節與美食，再預告本文會整理什麼。祭典完全不在開頭。
- 沒有任何一篇在開頭就給日期。

## 4. 關鍵問題怎麼回答

**一年有哪些祭典、各在幾月與會場**
- 沒有任何一篇做到。祭典整理類是「月份加活動名稱」當標題、日期藏在資訊清單；花火整理類是卡片（名稱、時間、地點）放在每區最前面，讀者掃卡片就知道。卡片這個做法最接近本頁需要的月曆。
- 結論：兩種都不用表格。我們用月曆表是跟他們不一樣的地方，也是這頁最能超越的地方。

**花火大會與海峽祭的日期、會場、壞天氣**
- 花火整理類的每場順序：日期時間 → 會場 → 看點 → 附帶攤位 → 交通 → 天候。壞天氣固定放在最後，句子很短，只說會不會延、延到哪天。
- 會場位置一律用「在某港、某公園、離哪個車站多遠」來講，不用地址。

**神社祭與水產祭怎麼看、怎麼去**
- 祭典整理類對傳統祭典是「來歷或特色」放最前，然後看點，最後才是資訊。所以神轎、小學生遊行這種看點會先講，交通最後帶一句。
- 這類頁的交通都是「從最近的車站步行幾分鐘」。禮文島沒有車站，所以要換成「從渡輪站、哪個港」。

**敦盛草感謝祭與馬拉松，遊客能不能參加**
- 台灣的禮文島攻略沒有講馬拉松。敦盛草只出現在花季說明，講的是「5、6 月看得到」，沒有講感謝祭。
- 祭典整理類沒有「遊客能不能參加」這個問題，因為他們選的都是對外開放的大祭典。

**船票與住宿**
- 祭典整理類不講；花火整理類只講交通（車站、開車時間），沒講住宿。
- Funliday 的 FAQ 與痞客邦都說夏天是旺季要早訂，這是台灣禮文島文章裡唯一的訂位提醒。

## 5. 段落與句子的習慣

- 祭典整理類：句子中長，多為陳述句，偶爾一句短句強調重點；段落三到五句；直接稱呼讀者（你、大家），結尾用邀請語氣；愛用波浪號與驚嘆號，語氣輕鬆。
- 花火整理類：句子偏長，常用頓號與「和」串多個資訊；愛用「各自」「各有」這類描述；日期格式統一寫月日加時分，數量用阿拉伯數字加單位；粗體標籤放在行首（「活動時間：」）。
- 禮文島攻略：口語，地名加粗，人名與關鍵詞加「」，直接稱呼讀者；常用「推薦」「絕對」等評價詞；FAQ 用「Q加問題」當標題。
- 痞客邦：第一人稱，常有感性短句與吐槽；價格統一用日圓符號，日文專有名詞放括號。
- 共通：台灣讀者看到的都是「活動叫什麼、哪天、在哪、怎麼去」四件事排成一個固定版型，每場長一樣。

## 6. 給作者的順序建議

標題是大綱定的，只調每一節裡的資訊順序。

**禮文島祭典與活動月曆（H2）**
1. 先給讀者一眼看完的整年輪廓：幾月有什麼、在哪。這是競品都沒做到的，月曆表放在最前，表格之後才用一兩句話說有哪幾個比較值得安排。
2. 接著說哪幾個是對外開放、遊客可以直接去看（花火、海峽祭、神社祭、水產祭），哪幾個是地方活動或報名活動，先分清楚，後面各節才不用重複。
3. 日期用當年公告的寫法時要標年份，因為 2027 年還沒公布。

**初夏的敦盛草感謝祭（H2）、最北花之馬拉松（H3）**
1. 這是台灣讀者最不知道的活動，先說它是什麼，再說日期與會場。
2. 馬拉松的 H3 是問句，先答「遊客能不能參加」，再說報名方式與日期。
3. 敦盛草的花期放這節，因為讀者最常問的是「看得到花嗎」。

**7 月中旬的神社祭與水產祭（H2）與三個 H3**
1. 先講看點（神轎、小學生帶頭、吃什麼），再講日期與會場，最後講怎麼從渡輪站過去。傳統祭典類競品的順序就是特色在前、資訊在後。
2. 嚴島神社祭與禮文神社祭分在島的兩頭，兩段各自先講在島的哪一側，再講日期。
3. 水產祭以吃的為主，先講吃什麼，再講日期。

**8 月的花火大會與海峽祭（H2）與兩個 H3**
1. 花火整理類的順序最合用：日期時間 → 會場 → 看點 → 攤位 → 交通 → 壞天氣。照這個排，壞天氣那節放在最後，是一個獨立的 H3。
2. 日期用月日加星期；會場用「在哪個港、離渡輪站幾分鐘」。
3. 海峽祭的美食攤與拔河，用一段說明看點即可，不用逐攤列。

**8、9 月的溫泉美食健行（H2）**
1. 這節大綱沒有 mustAnswer，是給讀者在沒有祭典的月份也有東西可做。台灣攻略講的是「花季」與「6 到 8 月」，沒有人講 8、9 月，所以先寫 8、9 月有什麼可安排，再接前後。

**看祭典的船票與住宿（H2）**
1. 先講「祭典那幾天船票與房間先被訂走」，再講怎麼排。台灣攻略唯一的相關提醒是「夏天是旺季要早訂」，我們可以用具體日期說清楚。
2. 順序：先船票（因為船班決定能不能當天往返），再住宿。

## 7. 他們有、我們缺的

這一頁沒有直接競品，所以下面列的是整理類頁讀者習慣看到、我們大綱與事實表沒有明講的題目。只列出來，由研究者回官方查，查不到就不寫。

- **當天的交通與時間安排**：花火整理類每場都寫從哪站步行、開車多久。禮文島要寫的是「花火在香深港，從哪個民宿走過去」「看完花火，還有沒有船或巴士」。大綱的「看祭典的船票與住宿」只講船票，沒有講看完之後怎麼回去。
- **座位、坐哪裡看**：花火整理類常寫有沒有收費席、哪裡人多。禮文島花火的觀賞位置事實表可能沒有。
- **打上發數**：台灣整理頁一定寫發數與規模。事實表要確認有沒有。
- **看點的來歷**：祭典整理類每項先講來歷。我們有神社祭、敦盛草感謝祭，但來歷（為什麼辦、辦了多久）事實表是否足夠，要回頭看。
- **攤位吃什麼、要不要帶現金**：海峽祭有美食攤，台灣讀者會問吃什麼；事實表有 F646、F650，但現金、入場費可能沒有。
- **雨天與服裝**：北海道夏天的海邊晚上很冷，花火整理類偶爾提醒外套；本頁大綱沒有這個題目，可看官方或氣象廳平年值有沒有可用的數字。
- **有沒有收費、要不要預約**：祭典整理類資訊清單有入場費。禮文島祭典多半免費，但要確認。
- **年份提醒**：台灣整理頁都寫「2026 年預定」。2027 年日期還沒公布，正文要標明是哪一年的公告，而且說清楚去年同期辦在哪一天，讓讀者先抓個大概月份。這是作者要處理的寫法問題，不是缺事實。
