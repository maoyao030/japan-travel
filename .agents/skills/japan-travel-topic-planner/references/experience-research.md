# 景點比對與體驗研究

2026-10-18 Darren 決定。地點研究（[選題流程](selection-workflow.md)第 5 步）每個地點多做兩件事，結果寫進群大綱。routine 自動規劃下一群時也照做。

只靠官方資料寫的頁面正確，但像說明書，少了讀者真正在意的事：大家實際去哪、現場有什麼麻煩、這地方和哪部電影有關、實際要待多久。這兩步就是補這些，同時確保官方列出的景點都有歸屬。

## 一、官方景點清單比對

1. 打開這個地點的官方景點清單，全部頁數都看：觀光協會、市町村觀光頁、北海道觀光機構等地區組織的「観光スポット」「見どころ」。
2. 每個景點在大綱的 `spotCoverage[]` 記一列：

| 欄位 | 內容 |
|---|---|
| `placeId` | 屬於哪個地點 |
| `nameJa`、`nameZh` | 日文名、繁中名（譯名照 `content-planning/glossary.json`） |
| `sourceUrl` | 官方清單或景點頁 |
| `decision` | `page`（負責頁）、`section`（寫在哪頁哪一節）或 `skip` |
| `articleId`、`heading` | `page` 與 `section` 要填 |
| `reason` | `skip` 必填：已停業、只開放團體、不是旅遊景點、查不到可用資料等 |

3. 官方清單沒有、但研究或下面的體驗研究找到的景點也加進來，`sourceUrl` 填查證用的官方頁。
4. 每個 `section` 都要真的出現在那頁的標題或必答問題裡，寫作時才不會漏。

## 二、體驗與文化切入點

### 去哪找

- **YouTube**，中文與日文都查（例如「禮文島 vlog」「礼文島 旅行」）。看標題、說明欄、章節列表、字幕與留言；章節列表直接告訴你創作者覺得哪些段落值得講。看不到畫面，所以不從畫面推論事實。
- **旅遊部落格與競品的行程頁**，中文與日文。
- 日文與中文 Google 自動完成裡和體驗有關的詞，例如「風 強い」「寒い」「混雑」「ロケ地」。

### 找四類線索

| 類型 `type` | 例子 |
|---|---|
| `route` 大家實際去哪 | 官方清單沒列、但大家都會去的拍照點或順路景點 |
| `hassle` 真實的麻煩 | 風大到站不穩、巴士班次少要配合時間、附近沒地方吃飯 |
| `culture` 文化連結 | 電影、動畫、歌曲的取景地，例如北方金絲雀公園是電影《北のカナリアたち》的外景地 |
| `timing` 時間感 | 一個景點實際要待多久、步道實際走多久 |

### 怎麼記

寫進大綱的 `experienceLeads[]`：

| 欄位 | 內容 |
|---|---|
| `placeId`、`type`、`summary` | 線索與一句自己的話 |
| `leadSources[]` | 在哪裡看到的網址（影片、部落格、競品頁） |
| `verification` | `official`（官方來源網址與事實編號）、`consistent-sources`（三個以上彼此獨立的來源說法一致，記 `R` 編號）、`unverified` |
| `useIn` | 寫進哪頁哪一節 |

### 規則

- **線索不是來源**。只有 `verification` 不是 `unverified` 的線索才能進正文。文化連結要用官方資料查證，例如電影官網、町公所或觀光協會的介紹。
- 客觀狀況（風大、坡陡、人多、班次少）依寫作 Skill 的「客觀狀況直接寫」，有官方資料或三個獨立來源一致就直接寫。
- 不轉述影片或部落格的內容，用自己的話寫結論；不寫成本站去過。
- 適合嵌入的影片或官方 Instagram 貼文，記進大綱的 `mediaPlan[]`，挑選條件見寫作 Skill 的 [嵌入與資料圖](../../japan-travel-answer-first/references/embeds-and-data-blocks.md)。
- 群外的線索（例如「很多人從旭川轉車」）照舊記進 [發現清單](discovery-log.md)。
