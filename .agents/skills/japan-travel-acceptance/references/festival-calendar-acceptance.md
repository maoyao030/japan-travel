# 祭典頁（一頁寫好幾個活動）的讀者驗收八題（2026-11-27）

給「一頁寫一個地方好幾個活動」的祭典頁（`aspect-page`、主題 `festival`，主要查詢是「○○祭典」，例如禮文島、利尻島、稚內）用，取代 [讀者驗收規則](reader-acceptance.md) 裡給一般頁型的判斷表；通則（只讀不改、寫位置與原因）照舊。一頁寫一個祭典的頁用 [festival-acceptance.md](festival-acceptance.md)。題目從〈禮文島祭典〉樣本整理出來，寫法依據是寫作 Skill `references/festival-calendar-page.md`。

## 讀者設定

已經排了要去這個地方（或這一帶）的台灣旅客，還在挑哪幾天去。住台北一帶，沒去過這裡，日文看不太懂，不開車。他帶著這些問題來：我去的那幾天有沒有活動、哪一個值得為它調日子、在哪裡看、看完回不回得去、要不要多住一晚。

驗收者先用這個身分把稿讀一遍，不看規格，記下：會不會為了哪個活動調日子、哪一句看不懂或覺得無聊、還有什麼疑問。再判八題。

## 驗收者讀什麼

- 這篇的 `reader-preview.md` 與 `publication.json` 的大標題、`excerpt`。
- 規格 `spec.md`、寫作 Skill `references/festival-calendar-page.md`。
- 同一型的範本（有登記時），做最後的「和範本比」。

不讀作者的說明、事實查核紀錄與偏好審查紀錄。

## 八題

每題判「過」「過（有一處要改）」或「不過」，附原句。

| 題 | 看什麼 | 不過的樣子 |
|---|---|---|
| 1. 最上面三樣 | 開頭先介紹這個地方，再帶進最值得排進行程的一兩段時間，各有一個畫面；最大的決定放在讀者身上；摘要兩三件事各自講完整 | 第一句是位置與距離；開頭列活動清單；摘要介紹文章自己；換個地方還能用 |
| 2. 挑得出日子 | 「○○祭典是什麼時候？」第一句就是答案；年曆表每一列都是遊客看得到東西的活動；日期的寫法下一年的讀者用得上 | 沒有答案只有表；表裡有要報名的比賽、不是祭典的活動、只有名字的活動；整欄是某一年的日期；寫了下一年找不到的日子 |
| 3. 主角有畫面、有背景 | 每個主角讀完腦中有畫面、知道為什麼會在這裡；份量明顯比表裡其他活動重 | 每個活動一樣重；主角寫成上一屆的節目時刻；背景是年表；同一個畫面講三次 |
| 4. 看完回不回得去 | 第一句就有答案；每個主角知道當天來回行不行、要住哪一區；會卡住的那一個照順序一步一句、照著做得到 | 只寫「注意末班船」；表上的時刻正文整段再唸；寫成渡輪頁（全部班次、票價） |
| 5. 每年會變的資訊 | 讀者分得出哪些每年固定、哪些是近幾屆的慣例；年份在正文只在必要的地方出現 | 「請到官網確認」「還沒公布」；一段連掛好幾個「近三屆」「近兩屆」「某年」，像在讀紀錄；往年的事被讀成下一屆已經確定 |
| 6. 沒有不該寫的 | 沒有別頁的事（旅館名單、各月氣溫、巴士路線）、主辦單位名單、路名與封路時段、只有某一屆才有的安排 | 有任何一項 |
| 7. 句子與用字 | 台灣說法、口語、關係有寫出來；大標題與每個 H2 唸出來是台灣人會講的話（Darren 退過「哪幾天最值得配合」）；一句最多 4 個逗號；沒有交代來源的口氣；同一個說法不重複 | 「公告都寫」「主辦自己這麼說」；「巡行」這類日文漢字詞；同一個賣點的說法全頁出現三次以上 |
| 8. 和別的比 | 比線上舊寫法（月曆加逐一活動的節目單）明顯好用；品質到同頁型或另一型祭典頁範本的水準；換個地名不能直接套 | 像量產頁；讀完只記得一張表 |

## 結論

- `acceptable`：八題都過，或只有不影響讀者的小瑕疵（列出來，作者順手改）。
- `needs_revision`：列必改的，每條引原句、說問題、說方向，不替作者寫定稿句。

另外列三句以內「讀者還想知道、頁面沒有」的事；查不到的不強求，交給協調者判斷要不要補研究。

交件寫在封包的 `acceptance-calendar.md`，第一行 `結論：acceptable` 或 `結論：needs_revision`。
