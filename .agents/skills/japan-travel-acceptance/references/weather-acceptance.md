# 天氣頁的讀者驗收八題（2026-11-26）

天氣頁（`aspect-page`、主題 `weather`）的讀者驗收照這八題，取代 [讀者驗收規則](reader-acceptance.md) 裡給一般頁型的判斷表；讀者設定以外的通則（只讀不改、寫位置與原因）照舊。題目與標準從〈禮文島天氣〉樣本的六次驗收（`content-production/rebun-island-weather/acceptance-weather.md`）整理出來，寫法依據是寫作 Skill `references/weather-page.md`。

## 讀者設定

已經決定要去這個地方，或正在兩三個月份之間選的台灣旅客。住台北一帶，沒去過這裡，日文看不太懂。他帶著這些問題來：我那個月去會多冷（跟台灣比）、要帶什麼衣服、天氣會不會讓我去不了或回不來、有什麼只有那時候才看得到、出發前要看哪裡。

## 驗收者讀什麼

- 這篇的 `reader-preview.md` 與 `publication.json` 的 `excerpt`（摘要）。
- 規格 `spec.md`、寫作 Skill `references/weather-page.md`。
- 同頁型的範本（`node scripts/page-models.mjs --for=<articleId>` 列的檔案），做最後的「和範本比」；還沒有範本時不做這一項。

不讀作者的說明、事實查核紀錄與偏好審查紀錄；事實對不對是查核者的事，這裡只看讀者讀起來的樣子。

## 八題

每題判「過」「過（有一處要改）」或「不過」，附證據（原句）。

| 題 | 看什麼 | 不過的樣子 |
|---|---|---|
| 1. 最上面三樣（大標題、摘要、序言） | 序言先用一兩句介紹這個地方，再帶進天氣；台灣讀者讀完就知道大概多冷、幾月好排、最要小心什麼；摘要只講兩三件事、和序言連著讀順、不整句重複 | 沒有介紹這個地方就直接講天氣；介紹的是距離與規格；摘要寫「這篇整理了…」或一句塞四五件事；序言講觀測站、平年值、氣候類型；開頭有把讀者帶走的指路句；換個地名還能用 |
| 2. 三十秒找到我那個月 | 挑兩個月份（一個夏天、一個冬天）實際找一次：幾度、比台北冷多少、穿什麼、要注意什麼，在兩張表裡找不找得到 | 要讀完好幾段才拼得出答案；某個月份兩張表都對不到；某一格只寫「看後面那一節」 |
| 3. 數字有沒有變成感覺 | 氣溫有拿台北當對照，換算的話讀者一聽就懂；自己拿表格把每一句換算對一次 | 只有日本的數字；兩排數字並列但沒有一句結論；換算不準 |
| 4. 表格唸兩次 | 表格上有的數字，正文沒有再逐月唸一遍 | 表後出現「N月平均X℃、早晚Y℃，所以…」連著好幾句；把停航表的數字再唸一次 |
| 5. 穿著 | 先有這個地方的原則；穿法拿台灣當基準、各列分得出差別；每一句都是換個地名就不成立的話 | 「帽子手套帶齊」「記得帶雨具」這類每頁都能用的句子；單品清單；「照冬天穿」沒說是哪裡的冬天；1 月和 4 月的穿法是同一句 |
| 6. 天氣會不會打亂行程 | 有數字、有結論（哪幾個月要多留一天，這一節自己要講到）、有停了怎麼知道；沒有把話說過頭 | 只寫「冬天常停航」沒有數字；寫成「夏天不會停航」；只看這一節不知道該怎麼做；改票方法寫了一大段 |
| 7. 這裡才有的天氣 | 讀者讀完能判斷「我那趟有沒有機會看到」：幾月、什麼樣的時候、在哪、要不要住一晚 | 在講成因（高氣壓、氣溫逆轉）；只說「有機會看到」沒有條件；地點只有名字 |
| 8. 不該寫的與通則 | 沒有極端紀錄堆疊、逐日紀錄、統計天數、會過期的日期、別頁的營業資訊；一件事全頁只講一次（第 6 題的結論除外）；連結句不套同一個句型；提醒接在具體事實後面；一句最多 4 個逗號；台灣說法、括號外沒有日文；標題樹照規格、問句標題下一段第一句是答案 | 有任何一項 |

四季總表另外看三件事：格子是不是太長（一格最多兩句）、五句定調是不是讀者記得住而且只有這裡成立的話、列與列之間有沒有重複。有一欄五列空了兩列以上，直接說這一欄該拿掉。

八題之後再寫兩件事：

- **輕重**：哪一節明顯太空（讀者照著做會卡住）列一定要改；哪一節明顯囉嗦、或每節一樣長，列可改可不改。正文 1,300 到 2,000 字（以 `check-voice.mjs` 算的為準）；不到下限但讀者沒有少東西，不算缺點。
- **讀完的感覺**：這頁讀起來像一個熟悉當地的人在說明，還是像在整理資料。指出最像整理資料的兩三句，也列最好的兩三句。

## 不要要求改回去的

- 照事實查核改保守的說法（「霧多」不寫成「霧最多」、步道封閉不列日期、來源打不開而拿掉的內容）。
- Darren 親口定的：開頭先介紹這個地方、第一個地名連回主頁而不另寫指路句、大標題、第 6 題的結論在開頭與那一節各講一次。

## 交什麼

`acceptance-weather.md`（第二次以後在同一個檔案往下加「第 N 次驗收」）：

1. 總判定：`acceptable`、`needs_revision` 或 `reject`。
2. 一定要改：每條寫位置、原句、哪一題、為什麼、最小改法（只指方向，不替作者寫整段）。只把真的會讓讀者卡住的列進來。
3. 可改可不改。
4. 逐題結果：題號、過或不過、證據。
5. 輕重與讀完的感覺。
6. 第二次以後：上次每一條「一定要改」解決了沒有。

八題全過、輕重沒有一定要改的，才是 `acceptable`。驗收者只讀不改稿。
