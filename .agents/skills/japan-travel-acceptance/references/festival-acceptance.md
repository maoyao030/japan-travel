# 祭典頁的讀者驗收八題（2026-11-27）

給「一頁寫一個祭典」的祭典頁（`aspect-page`、主題 `festival`，主要查詢是單一祭典的名字）用，取代 [讀者驗收規則](reader-acceptance.md) 裡給一般頁型的判斷表；讀者設定以外的通則（只讀不改、寫位置與原因）照舊。題目從〈層雲峽冰瀑祭〉樣本的兩次驗收整理出來，寫法依據是寫作 Skill `references/festival-page.md`。第 6 題另外看：轉車是不是照順序一步一步講完（這班車開到哪裡、幾點到、等多久、接哪一班、錯過會怎樣）；第 7 題另外看：冷不冷有沒有拿台灣人經歷過的基準比（寒流），不是兩排數字算差幾度（Darren 2026-11-27 在樣本通過驗收後挑出的兩處）。

## 讀者設定

冬天要去北海道、正在考慮要不要把這個祭典排進去的台灣旅客，或已經決定要去、來查這一屆日期與怎麼排的人。住台北一帶，沒去過這裡，日文看不太懂，不開車。他帶著這些問題來：值不值得專程去、這一屆什麼時候辦、幾點去、門票多少、看完回不回得去、要不要住一晚、會多冷。

## 驗收者讀什麼

- 這篇的 `reader-preview.md` 與 `publication.json` 的 `excerpt`。
- 規格 `spec.md`、寫作 Skill `references/festival-page.md`。
- 同頁型的範本（`node scripts/page-models.mjs --for=<articleId>` 列的檔案），做最後的「和範本比」；還沒有範本時不做這一項。

不讀作者的說明、事實查核紀錄與偏好審查紀錄；事實對不對是查核者的事，這裡只看讀者讀起來的樣子。

## 八題

每題判「過」「過（有一處要改）」或「不過」，附證據（原句）。

| 題 | 看什麼 | 不過的樣子 |
|---|---|---|
| 1. 最上面三樣（大標題、摘要、開頭） | 開頭先用一兩句介紹這個地方，再帶進祭典的畫面；讀完開頭就知道這一屆什麼時候辦、最大的那個決定是什麼；摘要只講兩三件事、和開頭連著讀順 | 第一句就是屆數與日期；介紹的是距離與規格；摘要寫「這篇整理了…」或一句塞四五件事；開頭有把讀者帶走的指路句；換個祭典還能用 |
| 2. 讀完會不會想去 | 「值得專程去嗎」的答案是只有這裡成立、讀者有感的理由；看點讓人知道到了會場會看到什麼，每個看點把一兩件事講完整 | 答案是空話；看點是設施清單、一件事半句；全是規格與價格；沒有畫面 |
| 3. 三十秒查到這一屆 | 實際找一次：哪一天到哪一天、平日與週末幾點開、門票多少、煙火幾點，在當屆資訊表裡找不找得到 | 要讀完好幾段才拼得出來；表上有的數字正文又唸一遍 |
| 4. 是不是上一屆的節目單 | 會變的數字只在開頭一句與當屆資訊表；正文講的是近幾屆都一樣的事，讀者分得出哪些是這一屆確定的、哪些是往年的慣例 | 每段都在講某一年幾點有什麼節目；出現「請到官網確認」「還沒公布」；讀者以為往年的事是這一屆已經確定的；「近幾屆」多到像在讀紀錄 |
| 5. 幾點去 | 讀完知道平日還是週末去、白天還是晚上去、晚餐怎麼排，有理由 | 只有開放時間，沒有判斷；判斷沒有理由 |
| 6. 看完回不回得去 | 第一句就有答案與原因；照自己想看什麼，在表裡找得到搭哪一班去、哪一班回、幾點到；要看煙火知道該怎麼辦；不開車的人照著做不會卡住 | 只寫「注意末班車」；要自己對時刻表才知道接不接得上；寫成另一頁交通頁（車資、全部班次、路線名稱） |
| 7. 多冷 | 一句就知道比台北冷多少；有這個會場才有的事（哪裡可以取暖、現場買得到什麼） | 只有日本的數字；「帽子手套帶齊」這類每頁都能用的句子 |
| 8. 不該寫的與通則 | 沒有別頁的事（全部班次、旅館名單、各月氣溫表）、洽詢電話、場內小額費用、會場動線；一件事全頁只講一次；連結行寫的是那一頁有的東西；一句最多 4 個逗號；台灣說法、括號外沒有日文；標題樹照規格、問句標題下一段第一句是答案 | 有任何一項 |

八題之後再寫三件事：

- **輕重**：哪一節明顯太空（讀者照著做會卡住，或讀完不知道值不值得去）列一定要改；哪一節明顯囉嗦列可改可不改。正文 1,500 到 2,200 字；不到下限但讀者沒有少東西，不算缺點。
- **最後一節**（其他季節的活動）：對這頁的讀者有沒有用，還是像硬塞。
- **讀完的感覺**：像一個熟悉當地的人在說明，還是像在整理資料。指出最像整理資料的兩三句，也列最好的兩三句。

## 不要要求改回去的

- 照事實查核改保守的說法：煙火只寫「近兩屆每晚 20:30」、看點寫「近三屆」「近四屆」、不寫建議待多久與什麼時候人多（沒有可靠來源）、不寫第 52 回還沒公布的事。可以指出讀起來卡，但不能要求寫成確定。
- Darren 親口定的：大標題帶年份、會變的數字集中在一張表、開頭先介紹這個地方、第一個地名連回主頁而不另寫指路句。

## 交什麼

`acceptance-festival.md`（第二次以後在同一個檔案往下加「第 N 次驗收」）：

1. 總判定：`acceptable`、`needs_revision` 或 `reject`。
2. 一定要改：每條寫位置、原句、哪一題、為什麼、最小改法（只指方向）。只把真的會讓讀者卡住的列進來。
3. 可改可不改。
4. 逐題結果：題號、過或不過、證據。
5. 輕重、最後一節、讀完的感覺。
6. 第二次以後：上次每一條「一定要改」解決了沒有。

八題全過、輕重沒有一定要改的，才是 `acceptable`。驗收者只讀不改稿。
