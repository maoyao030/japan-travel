# 讀者驗收規則

## 讀者設定

你是第一次去日本小地方、不會日文的台灣旅客。你打算照著這篇文章安排整趟行程。

## 第一階段：只讀文章

先不看研究記錄、事實查核結果或作者計畫。記下閱讀判斷後才進第二階段。

### 1. 開頭與核心答案

- 開頭有沒有用一小段具體情境接到核心答案？泛用背景或「你是否也……」不算情境。
- 讀到哪裡就能得到主要答案？之前的內容是否都必要？
- 全文有沒有真正回答頁面規格的主要問題，沒有暗自縮成好寫的子題？

### 2. 模擬走一遍

把文章當成行程手冊，從出發地一路走到目的地再回來。每一步問：

- 我知道要去哪裡、找什麼標示嗎？
- 遇到日文網站或日文標示，文章有給我對照嗎？
- 需要跟人說話時，有可以指給對方看的句子嗎？
- 錯過班次、船停駛、旅館聯絡不上時，我知道怎麼辦嗎？
- 要付錢時，我知道能不能刷卡、要準備多少現金嗎？
- 需要認出某個地方時，文章有照片，或有清楚的文字描述（照片列在待拍清單時）嗎？

任何一步卡住，就記下位置與卡住的原因。這是保母等級的核心，卡住的步驟屬於讀者價值缺陷。

### 3. 主次與重複

- 找出最弱的一節，說明刪掉後少了哪個答案，判斷是否值得目前的篇幅。
- 各地相同的操作是否在本篇重寫了一大段，而不是連到共用教學頁？
- 泛用提醒（注意安全、提早規劃、以現場為準）是否取代了具體步驟？
- 同一個結論在開頭、表格、正文、FAQ 反覆出現時，每次有沒有新增條件或做法？

### 4. 標題

- 列出純標題 H 樹。H2 是否是主要分章，H3 是否真的屬於父題？
- 逐一檢查每個 H2／H3：是在命名本節的地點、步驟、問題，還是把正文提醒搬成小標？
- 「交通方式」「注意事項」這類無法辨識地點的泛稱是缺陷。
- 問句標題的下一段是否立即回答？
- 第二階段再對照計畫裡的 SEO Title 或「暫沿用 H1」；找不到就是 `not_checked`。

### 5. 常見問題

長篇是否從頁面規格的 `mustAnswer` 與相關問題中，回答了正文沒直接處理的問題？FAQ 是否只是把正文換成問句？

## 第二階段：對照研究與事實查核

- 打開研究記錄，看第一階段發現的缺口是作者查不到，還是查到了沒寫。
- 看 `fact-check.json` 的結果，確認讀者驗收中提到的事實都已被查核。
- 頁面規格的每個 `mustAnswer` 是否都有回答，或寫明查不到與替代做法。
- 住宿段落的訂房管道與查核日期是否齊全。

## 校準案例

| 情況 | 應有判斷 |
|---|---|
| 渡輪段落只寫「可搭渡輪前往，詳見官網」 | 讀者價值判退；讀者不知道班次、怎麼買票、到碼頭找什麼 |
| 寫出日文訂票頁的按鈕對照與售票口位置 | 可接受，這是保母等級的核心 |
| 「旅館官網沒有寫是否接受信用卡，建議訂房時以電子郵件確認」 | 可接受；明說查不到並給替代做法 |
| 推測「應該可以刷卡」 | 事實判退；查不到的事不能寫成確定 |
| 在利尻島條目重寫一整段整理券的用法 | 主次缺陷；應連到共用教學頁，只寫在地差異 |
| H2 為「交通方式」「住宿推薦」「注意事項」 | 標題缺陷；無法辨識地點，且「注意事項」是泛稱 |
| H2 為「先訂船票再訂旅館」 | 標題缺陷；正文提醒搬成小標 |
| H2 為「禮文島冬天能去嗎？」，下一段立即回答 | 可接受 |
| 開頭先寫三段北海道概況才講到禮文島 | 開頭缺陷；泛用背景延後了核心答案 |
| 只寫一個明確問題的共用教學頁，沒有 FAQ | 可接受，不因沒有 FAQ 判退 |
| 價格寫「約 3,000 日圓」但沒寫含稅或未稅 | 事實條件不完整；退回作者補上 |
| 碼頭售票口沒有照片也沒有位置描述 | 讀者價值缺陷；現場辨識要有照片，或在待拍期間用文字說明位置 |
| 每個 H2 都配一張風景照 | 主次缺陷；裝飾圖不回答讀者問題，退回選圖重新依需求判斷 |
