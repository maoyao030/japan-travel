# 地點百科先行的流程（設計草案，2026-10-18）

Darren 與 Claude Code 2026-10-18 討論後的方向。Darren 已同意大方向；細節由 Fable 子代理審查後再定。實作前不取代現行 Skill 與 routine 規則。

## 為什麼要改

現行流程是「先用自動完成決定要寫哪些頁，再為這些頁收資料，再寫」。稚內群研究後看到三個問題：

1. 寫到一半才發現資料沒查齊，例如沒查自行車、計程車車資、步行時間。讀者的交通情況（不開車、沒有自行車、想騎自行車）因此被漏掉。
2. 研究時才找到的題材（《南極物語》、北方金絲雀公園的電影、海豹、鋼彈人孔蓋卡、白色戀人包裝上的利尻山），規劃時沒有機會判斷要不要成頁。
3. 併頁要等研究完才知道，例如禮文島天氣與祭典資料不足 15 筆，研究後才併進主頁。

## 新流程

| 步驟 | 做什麼 | 產出 |
|---|---|---|
| 1. 地點百科 | 每個地點照固定欄位查到完整；查不到的寫明缺口種類 | 地點事實表（Git）＋百科欄位對照＋缺口清單 |
| 2. 機會盤點 | 百科（有哪些資料可寫）對照搜尋需求（自動完成、讀者在搜什麼），決定成頁、併頁、新題目 | 頁面規格 |
| 3. 群大綱 | 分工、H 樹、事實編號、內連、寫作順序（照現行） | 大綱 JSON |
| 4. 寫作前重查 | 該篇用到的會變事實（班表、價格、營業時間、活動日期）再查一次 | 更新事實表 |
| 5. 寫作與驗收 | 照現行四層驗收，加上口吻與標點檢查 | 文章封包 |

## 一、百科欄位

### 地點層（每個地點一份）

**必填**（查不到也要寫缺口種類）：
- 概要：這是什麼、為什麼有名、適合誰、建議停留時間。
- 四季：旺季、冬季能不能去、哪些設施冬季關閉。
- 怎麼到：從出入口的每一種方式，含時間、價格、班次、預約、末班、停駛公告。
- 當地交通：開車或租車、路線巴士、觀光巴士或接駁車、自行車、步行、計程車六種；租車行與租自行車的店（地點、季節、預約、價格）；票券；付款方式。
- 氣候：氣象廳平年值。
- 住宿清單與訂房管道。
- 活動月曆。
- 官方資源清單：觀光協會官網、中文頁或中文社群、時刻表、即時運行狀況、官方地圖 PDF、預約頁。

**有就記**（官方有寫才記，不主動追查）：手機訊號、醫療、野生動物、官方外觀形容、文化故事（電影、歌曲、地名由來）、體驗線索（YouTube、部落格，查證後才用）。

### 地點裡的東西（每筆一張卡）

| 類型 | 欄位 |
|---|---|
| 景點 | 身分、官方外觀形容、看點、開放期間與時間、費用、建議停留時間、「怎麼去」表（六種方式）、停車、廁所、照片來源、日文名 |
| 步道 | 起訖點、距離、時間、難度、開放季節、起訖點怎麼去、規定、廁所與水源、封閉 |
| 住宿 | 區域、房型、含餐、價格帶、營業期間、接送、訂房管道、查核日期 |
| 餐廳 | 招牌料理、營業時間與公休、季節限定、付款、排隊或預約 |
| 活動 | 日期、地點、內容、前一年實際日期、今年是否公布、活動期間的交通與住宿 |
| 交通路線 | 經營者、路線、班次、車資、季節班表、預約、停駛公告 |

### 「怎麼去」表

每個景點六格都要填：開車、路線巴士、觀光巴士或接駁車、自行車、步行、計程車。沒有的寫「沒有大眾運輸」，查不到的照缺口種類處理。資料在研究階段補齊，大綱檢查程式擋住空格。

## 二、資料放在哪一頁

- 「怎麼去」的細節由交通頁負責：每個地點的交通頁固定有一節「沒車怎麼去各景點」，用「怎麼去」表展開。
- 景點頁與主頁只寫一兩句最順的去法，再連到交通頁那一節。
- 寫作順序：每個地點先寫交通頁，景點頁在後，地點主頁最後（現行大綱已是這樣）。
- 兩邊用同一份事實與編號；景點頁若意外先上線，連結記成待補內連。
- 置物櫃放交通頁的車站或渡輪站一節；步道安全（例如沒有訊號）放健行頁；觀光案內所、現金與 ATM、醫療放地點主頁靠後的「實用資訊」一節。不寫 110、119 這類一般常識。

## 三、缺口的五種類型與處理

| 種類 | 例子 | 正文寫法 | 重查 |
|---|---|---|---|
| 1. 沒有官方網站 | 宗谷岬計程車車資、小店營業時間 | 業者名稱與電話，寫「官方沒有公布，請洽…」 | 每年一次 |
| 2. 官方網站沒寫這一項 | 步道距離、巴士站走到景點的時間、開山日 | 用其他確定的事實組成建議（例如「最晚趕上 15:29 的末班」） | 每年一次 |
| 3. 還沒公布 | 明年祭典日期、夏季班表、風車工程明年安排 | 寫今年的實際日期並標年份；固定規則可以寫 | 依公布時程（例如 5 月、4 月底） |
| 4. 官方說法不一致 | 船上小賣部、飯店營業期間、溫泉公休日 | 採經營者自己的來源，研究紀錄記差異；必要時提醒出發前確認 | 短期內再查 |
| 5. 只有非官方來源 | 電影台灣片名、歌曲演唱者 | 三個以上獨立來源一致才寫，否則不寫 | 不定期 |

### 缺口進 D1

- 現在：已查到的事實，查核狀態與到期日在 D1 `facts`；事實本身在 Git 的地點事實表。稚內群 748 筆還沒同步（現行流程在發布時才同步）。
- 要加：D1 新增「待補事實」表（缺口種類、地點、問題、下次查的日期、查到後要補進哪個地點）；同步程式把缺口登記進去；routine 的事實重查連缺口一起查。
- 查到新資料時，routine 記一筆例外「這筆資料可以補了」，由規劃 session 補進事實表；routine 依規則不直接改規劃檔。

## 四、寫作規則（同時定稿中）

研究見 `content-experiments/voice-study-2026-10-18/`。

- **導覽編輯口吻**：先說身分，用條件句寫畫面，印象標出處，推薦由事實推出，不寫成本站去過。
- **資訊完整**：每個景點有基本資訊欄；每頁最後有「延伸資料」（只列官方）；地點主頁有「依旅客類型的排法」（不開車、想騎自行車、只搭巴士、不想走太多路、想健行）。
- **像人寫的**：中英數之間不加空格；不用分號；冒號只放在條列前；括號只放原名；平均句長 28～38 字；「的話」「不妨」減量；用「前往、抵達」不用「來這裡」。用 `check-voice.mjs` 檢查。
- **圖片**：每個景點一張「認得出現場」的照片，依序用維基共享資源、免費圖庫、條款允許的觀光協會照片、官方帳號嵌入；缺圖是常態，不用 AI 圖代替現場照片。
- **嵌入影片與資料圖元件**：網站元件還沒做。

## 五、稚內群怎麼套用

不重做，只補齊：

1. 定好百科欄位與檢查程式。
2. 掃描現有的 4 份事實表與研究紀錄，列出缺的格子。預期主要缺「怎麼去」表、官方外觀形容、實用資訊、官方資源清單。
3. 派子代理補齊。
4. 做一次機會盤點。
5. 缺口登記進 D1。

## 已知的限制

- routine 每輪只做一件事、一輪最多新寫一篇；百科與機會盤點是規劃 session 或 routine 的「規劃下一群」在做。
- Darren 沒有開發經驗，所有決策要用白話呈現。
- 一群的研究成本：這次 4 個子代理各約 30～35 分鐘、40～50 萬 token。

## 審查後的修正（Fable 子代理，2026-10-18）

審查結論：方向對，但下面幾處要改。Darren 確認後實作。

| 原設計 | 改成 | 原因 |
|---|---|---|
| 每個景點六格「怎麼去」表 | 每個景點只記**最近的交通節點**（巴士站、港口、車站、停車場）與**最後一段**（走幾分鐘、停車、季節限制）。六種方式只在節點記一次，放交通頁 | 182 個景點乘六格是 1,092 格，一半只能填「不適用」；很多景點其實是同一站下車走幾分鐘 |
| D1 新增「待補事實」表 | 缺口直接當成一筆事實寫進事實表（`kind: "gap"`、`gapKind`），D1 只加一個欄位；現有重查機制照用 | 少一張表、少一套同步；補上時直接把缺口改成一般事實 |
| 五種缺口 | 拆成兩欄：**原因**決定寫法，**下次查核日**另外填。原因加兩種：「來源存在但這次讀不到」與「未查」；刪掉「只有非官方來源」（回到體驗線索的查證狀態） | 55 個缺口裡至少 9 個是 PDF 是圖片、網站擋機器人，官方其實有寫；寫成「官方沒有公布」是事實錯誤 |
| 寫作前重查要更新事實表 | routine 在生產那一輪有**窄權限**：只能改這篇引用的事實的主張、摘錄、查核日，不能新增刪除；規劃檢查要通過 | 現行規則禁止 routine 改規劃檔，原設計做不到 |
| 發布時才同步事實到 D1 | 規劃完成就同步 | 宗谷岬有幾筆 11、12 月到期的重查，不同步就會漏查 |
| 交通頁依景點列 | 交通頁依**節點**寫（「宗谷岬站下車走得到的地方」） | 之後新增景點不用改已上線的交通頁 |
| 「官方沒寫」每格都寫 | 不適用的格子不顯示；「官方沒寫」只在讀者會問的格子出現，每頁正文最多 3 句 | 避免整頁像免責聲明、像程式產生 |
| 研究查到完整為止 | 每個地點給時間預算，沒查到的格子標「未查」；「有就記」設白名單與上限 | 研究沒有停止條件 |
| （沒有） | 推算的事實記「算自哪幾筆」，來源變了一起標記 | 例如當天來回三種排法是從時刻表算出來的，改點時要連帶更新 |
| 機會盤點是獨立步驟 | 併進現有研究輸出；已核准的群可「追加頁」，每群最多 3 頁，走默許核准 | 少一個流程名詞，核准規則明確 |

補充的旅客需求：寄放行李、自行車上船與上巴士、廁所冬季封閉、停航停駛時怎麼辦（集中在主頁實用資訊）、無障礙（只記官方寫的）、哪些交通只收現金、日出日落、冬季道路通行資訊。

建置順序：
1. 格式與檢查程式。
2. 事實同步到 D1 並加欄位。
3. 改規則（窄權限、讀不到的處理、「官方沒寫」上限）。
4. 稚內群補資料。
5. 渡輪頁整篇測試。
6. 寫作前重查接進 routine。
7. 追加頁規則。
8. 延後：規劃下一群拆成多輪、換季時的數值自動替換。
