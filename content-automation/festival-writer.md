# 祭典頁的自動寫作流程（一頁寫一個祭典，2026-11-27）

排定工作 `japan-travel-daily-writer` 挑到「以一個祭典為主題」的祭典頁（文章清單裡 `pageType` 是 `aspect-page`、主題是 `festival`，而且頁面規格的主要查詢是單一祭典的名字，例如「層雲峽冰瀑祭」）時，不照 `local-writer.md` 第 2～4 步，改照這份文件做，做完接 `local-writer.md` 第 5 步上傳。

一頁寫一個地方好幾個活動的祭典頁（主要查詢是「○○祭典」「○○活動」，例如稚內、利尻島、禮文島）**還沒有寫法，不照這份寫，挑到就跳過**。

這套流程是 2026-11-27 人工 session 做〈層雲峽冰瀑祭〉樣本時用的。寫法的規則在寫作 Skill，這份只管順序、派誰做、卡住時怎麼辦；沒寫到的細節照 `weather-writer.md` 同名的步驟。

- 寫法：`.agents/skills/japan-travel-answer-first/references/festival-page.md`、`core-style.md`、`writing-guide.md`、`sentence-rhythm.md`、`examples.md` 第 6 節。
- 偏好審查：`.agents/skills/japan-travel-answer-first/references/preference-review.md`（A～K 題）。
- 讀者驗收八題：`.agents/skills/japan-travel-acceptance/references/festival-acceptance.md`。
- 前例：`content-experiments/festival-page-study-2026-11-26/sample-sounkyo-festival/`（`spec.md`、`reference-review.md`、九輪 `fact-check.json`、`preference-review.md`、`acceptance-festival.md`）。

## 什麼時候用

1. **有範本**：`node scripts/page-models.mjs --for=<articleId>` 的 `ready` 是 `true`。沒有就跳過。
2. **同地點的主頁已有可用的事實**（開頭介紹這個地方要用）。
3. **同地點的交通頁已上線，或交通經營者的時刻表查得到**（「回不回得去」要用）。

## 模型與角色

| 角色 | 模型 | 備註 |
|---|---|---|
| 研究者 | Opus 5.5 | 不是作者 |
| 作者 | Sonnet 5.5 | 一篇一位，退回修改用 SendMessage 回同一位 |
| 事實查核、偏好審查、讀者驗收、標題檢查、選圖 | Opus 5.5 | 各派一位，都不能是作者；彼此也不能是同一位 |
| 協調者 | 不寫正文 | 寫規格、整理事實表、跑程式、組封包；只套用查核者、審查者給的可原樣套用的最小改法，套完一定送查核 |

和住宿頁、地點主頁、天氣頁同一個組合；這是結構提案列的預設，Darren 沒有另外表示意見。任何角色都不用 Fable。

## 步驟

產出放在 `content-production/<id>/`。子代理等它完整回傳、親自確認檔案存在才做下一步。

### 0. 規格（協調者）

標題照 `festival-page.md` 的結構重排，寫成 `spec.md`（格式照樣本的 `spec.md`）。舊大綱的標題不適用「一字不改」。

- H1 與第 2 節的 H2 帶當屆年份。次要查詢要在 H1 或某個 H2 看得到；還沒公布的事不能放進標題當成確定（寫「近年」）。
- 屬於別頁的 mustAnswer 列進「交給別頁、這頁不寫的」。
- 連結行寫的內容，先對過那一頁真的有。
- 這個地方其他季節的活動：有別頁負責就不設第 5 節、只放連結；沒有才設，並照選題 Skill 記成合併候選。

### 1. 研究與事實表（研究者）

照 `local-writer.md` 第 2 步第 0 點補研究，祭典頁要有的：

- **當屆公布到哪裡**：主辦官網首頁、會場圖、交通、購票各頁（HTML 註解裡的字不算公布）、主辦單位的新聞稿、官方行事曆。分清楚哪些字寫的是這一屆、哪些是上一屆留下的。
- **近三到四屆的比對**：用官網的網頁存檔對每一屆的會場圖與首頁，列出每個看點、每個節目連續幾屆都有，日期、時間、費用各屆怎麼變。這張比對決定正文每一句的強度。
- **和交通對不對得上**：經營者官方的時刻（祭典期間適用的那一版）、主要節目的時間、末班車往哪裡、隔天頭班。寫進「推算」表。
- **有感的基準**：氣溫用當地最近的氣象廳平年值，配中央氣象署對寒流的定義或台北的平年值。
- **和同類祭典比**：只記對方官方、不太會變的事；做法其實一樣就寫明「不能說做法不同」。
- **建議待多久、什麼時候人多**：只收官方、經營者或三個獨立來源一致的說法，查不到就明講查不到。
- **開頭介紹這個地方用的事實**：從同地點主頁的研究紀錄照抄。

判定：當屆的日期沒公布、近幾屆的比對做不出來（沒有存檔）、或交通時刻查不到，就不寫（停放）。

### 2. 作者（Sonnet 5.5）

讀 `spec.md`、`core-style.md`（先讀）、`festival-page.md`、`writing-guide.md`、`sentence-rhythm.md`、`examples.md` 第 6 節、同頁型範本與 `reference-review.md`。不上網。交 `draft-tagged.md`、`publication.json`、`gaps.md`、`order-notes.md` 的 `## 和範本比`（跑 `check-copy.mjs`）。

### 3. 程式初檢（協調者）

`fact_tags.py`（要 `tags_clear`）、`check-voice.mjs`。同一個問題退三次還不過就停放。

### 4. 事實查核與偏好審查（Opus 5.5）

第 1 輪兩位同時審同一版，意見一起退回作者；之後每一輪改完都重跑第 3 步、兩邊複查。事實查核最多 4 輪大改（只套用最小改法的確認不算），偏好審查最多 3 輪。

- 事實查核照 `fact-check-contract.md`，祭典頁特別查：說過頭（每年、都、只有、沒有變過）、還沒公布的事有沒有被寫成確定（含大標題、H2、摘要的暗示）、推論的畫面、每一班車的時刻與銜接、和別的祭典比的句子、連結行寫的東西那一頁有沒有、資料來源的標題是不是真正的標題。
- 偏好審查照 `preference-review.md` A～K 題，另外看：看點有沒有只有一句或一段塞三件事、「近幾屆」是不是每段各掛一次、轉車有沒有照順序一步一步講、數字有沒有換成讀者有感的基準。
- 兩邊衝突：事實與強度聽事實查核，語氣在那個強度之內調。審查者示範的句子一律送查核。
- 第 3 輪以後還剩的，只差斷句或一兩個詞就套用審查者給的可原樣套用的改法；要重寫段落的停放。

### 5. 讀者驗收（Opus 5.5，最多退 4 次）

照 `festival-acceptance.md` 八題，寫 `acceptance-festival.md`。`needs_revision` 退回作者，改完重跑第 3、4 步。驗收者與查核者意見相反時（驗收要畫面、查核說只有一屆），照事實的上限寫並標年份，不取消強度。

### 6. 標題檢查與程式檢查、7. 驗收紀錄與定稿檢查、8. 照片與上傳、9. 記錄

照 `weather-writer.md` 第 7～10 步。照片與貼文的數量照 `festival-page.md`「照片與貼文」；封面單獨派、先交。照片標拍攝年份。

## 預設做法（不用問 Darren）

| 情況 | 做法 |
|---|---|
| 當屆的某一項還沒公布（煙火時間、購票方式） | 寫近幾屆的慣例並標年份；沒有慣例就不寫。標題不放那一項，或加「近年」。記進 `gaps.md` 與重查日期 |
| 看點只有一句話可寫 | 併成一段不設小標題，或拿掉；看點數量不規定 |
| 畫面只有一屆的依據 | 正文標年份，不進小標題 |
| 「建議待多久」「什麼時候人多」查不到 | 不寫 |
| 官網的會場圖頁改版、舊內容進了 HTML 註解 | 用網頁存檔當來源並列進資料來源 |
| 同類祭典的做法其實一樣 | 只比辦多久、開到幾點這類站得住的差別 |
| 這個地方其他季節的活動沒有頁負責 | 設第 5 節各兩三句，記成合併候選 |
| 大標題 | 照 `festival-page.md` 的結構，帶年份；偏好審查者另提 3 個候選記在封包裡 |
| 字數不到 1,500 但驗收說讀者沒少東西 | 不補字 |

## 要停下來留給 Darren 的事

- 只有 AI 圖可用。
- 這頁太薄（當屆資訊加看點不到短頁門檻），要併進主頁。
- 要新增頁面（例如其他季節的活動找到可以收的詞）。
- 要改已上線的其他頁面。

## 停放與每篇做完

照 `weather-writer.md`。`unattended-summary.md` 另外寫：當屆還沒公布的項目與預計重查日、交通時刻適用的版本與下次要查的時間。

## 每年更新

官方公布下一屆時（事實表到期日）：重查當屆資訊、近幾屆比對加一屆、交通時刻；更新大標題與 H2 的年份、開頭那一句、當屆資訊表、來回小表；改過的句子送事實查核。這是已上線文章的修正，走 `RULES_OVERVIEW.md` 第 11 節的流程。
