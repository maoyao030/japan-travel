# 日本旅遊長尾站｜交接文件（2026-10-15）

這份文件給**新 repo 的第一個 Claude Code session** 讀。它記錄 Darren 與 Claude Code 在好材誌 repo 的對話裡，對第二個站做出的所有決定與查到的數據。新 session 開始時：先用 `add_repo` 以唯讀方式掛上 `maoyao030/building-materials-tw`，讀本文件、`AGENTS.md`、`scripts/article-automation-policy.mjs`、`.agents/skills/building-materials-tw-answer-first/` 與 `building-materials-tw-auto-publisher/`，再開工。本文件不是發布授權；每頁仍要 Darren 核准進清單。

## 一、定位（Darren 2026-10-15 決定）

- 站名與網域未定。主題是「**台灣人去日本旅遊的長尾實用資訊**」，不是美食站。
- 篩選原則：**OTA 庫存蓋不到、大型日旅品牌（KKday、Mimi韓等）不寫的題目**。不是「沒有轉單價值」，是「他們蓋不到」。
- 收入結構：住宿頁是主幹（Trip.com 與 Agoda 分潤＋廣告），天氣與季節頁是流量墊腳與內連來源，美食當配角。
- **分潤原則與好材誌不同**：本站開放 Trip.com 與 Agoda 聯盟分潤（兩者台灣可申請、銀行匯款、門檻皆 200 美元）。Jalan 走日本 ASP 需日本銀行帳戶與日文站，台灣拿不到；樂天 Travel 報酬是樂天 Pay 餘額且多語版預約自 2022-05-31 不算成果，對台灣讀者等於零。KKday 有上架的團體行程可走 KKday 分潤。
- 仍不做：廠商名錄式內容、Tabelog／Google 評論改寫、搬家公司推薦類清單。
- AdSense **先不掛**。AdSense 違規是帳號層級，會連帶好材誌。等有流量、驗收穩定後再申請加站。

## 二、三類題目與 Ahrefs 數據（台灣市場，2026-10-14 至 15 查）

| 日本梅雨季 | 800 | 450 | 1 美分 |
| 東京11月天氣 | 600 | 250 | 無 |

| 北海道12月天氣 | 350 | 200 | 8 美分 |

| 北海道冬天穿搭 | 200 | 150 | 無 |

- 「東京天氣」21,000、「大阪天氣」13,000 等是查預報，Google 天氣卡直接回答，母題為「東京天氣預報10天」，**不寫**。
- 能寫的是「城市 × 月份」與季節事件。資料來源：氣象廳平年值（公開、三十年不變、可驗收）。約 10 城市 × 12 月＝120 頁加季節頁。每題都有 AI 摘要，第一名實得多半低於搜尋量。
- 關鍵字寫法要用無空格形式查（「東京11月天氣」有 600，「東京 11月 天氣」只有 10）。

| 城崎溫泉 住宿 | 100 | 無資料 | | |
| 草津溫泉 住宿 | 90 | 250 | | |

- 廣告單價是美食的 10 到 30 倍。小站排得上。
- 事實來源：旅館官網（多有繁中或日文官網）、Jalan／樂天 Travel 頁面只當核對用。**不存**營業資訊進正文以外的地方。
- 收入兩層：Trip.com 或 Agoda 有上架的放分潤連結；只有官網或 Jalan 的放官網連結、不收錢，價值是頁面完整度。
- **更新機制是新需求**：每頁帶查核日期，每年重查官網一次（價格、含餐、歇業、改裝）。好材誌流程沒有這條，要新建。

### 地名 × 美食、料理知識（配角）

- 18 個日本城市「某地美食」每月 150 到 1,000，合計約 9,000；10 個「地方 × 料理」知識詞合計約 13,000。
- 只寫第一名實得流量大於搜尋量的格子：小樽美食（450／1,700）、鎌倉美食（450／1,300）、廣島美食（600／900）、仙台、長崎、奈良（各約 600）、札幌湯咖哩（250／600）、博多拉麵（2,600／350）、函館朝市（500／500）。
- 定義型知識詞（讚岐烏龍麵 3,800／40、宇治抹茶 800／20、名古屋鰻魚飯 1,000／0）被 AI 摘要吃掉，不寫。
- 「台灣人在日本吃飯的實際問題」（小費、刷卡、お通し、續麵、素食、英文菜單等 20 題）查無量：13 題不在資料庫、6 題為 0，只有「tabelog 分數」250。不當主線。
- 城市大詞（大阪美食 2,200、京都 1,200、東京 1,200）前十名是 TripAdvisor、HK01、Trip.com、Agoda、觀光局，DR 67 到 89，不碰。

### 選題陷阱

- **台灣同名地名**：「岡山美食」8,600 是高雄岡山、「松山美食」1,000 是台北松山。中山、板橋、豐原等同理。每題必須人工或 SERP 確認意圖，不能只看量。
- Ahrefs 顯示 10 的詞多為雜訊，一頁要抓一組變體。

## 三、評論與圖片的規則

- **Tabelog**：條款第 6 條禁止營利目的存取、無斷利用口コミ（每則可索 1 萬日圓），第 8 條禁止翻案。實務上改寫段落幾乎查不到、法律上事實與觀點彙整不構成侵權，但**排名問題大**：Google 地圖包與 Maps 的 AI 評論摘要已經在做同一件事。結論：不改寫評論；評價層只放公開榜單事實（米其林、Tabelog 百名店、Tabelog Award）加連結。
- **Google 評論與照片**：Places API 禁止預抓、快取、儲存（place ID 除外），顯示須署名並連回 Maps；直接爬 Maps 違反服務條款。Maps 照片著作權在上傳者。
- **合法圖片來源**（由便宜到貴）：卡片不放店家照片、整篇封面用免費圖庫；Google Maps 嵌入 iframe（免費，每篇 1 到 3 間）；Hot Pepper Gourmet Web 服務 API 照片（免費、須署名「Powered by ホットペッパーグルメ」、收錄偏連鎖）；店家 Instagram 官方嵌入；Wikimedia Commons（料理與地標，CC 授權）；Places 照片 API（合法但每千次 7 美元，不可行）。不用對方網頁 OG 圖當卡片。
- **Hot Pepper API** 回傳店名、地址、營業時間、預算、類型、照片、店家一句話，可作店家營業資訊的合法來源。文件：webservice.recruit.co.jp。

## 五、技術與流程

- **直接沿用**：Astro、Sanity、Cloudflare Workers Static Assets、GitHub；`scripts/article-automation-policy.mjs` 的清單結構、鎖、每日上限、驗收迴圈、CI 檢查（站內連結、結構化資料）；answer-first 的作者／驗收者分離、WHOOPS 標題規則、無制式摘要；stock-image-finder 的免費圖庫流程。
- **要改寫**：answer-first 與驗收 Skill 的事實來源規則（觀光廳、各地觀光協會、氣象廳、國稅廳、消費者廳、旅館與店家官網）；分類樹（住宿／天氣季節／美食／交通）；圖片規格（店家卡片不放照片）；新增住宿頁年度重查 routine；清單加「訂房管道」欄（官網／Trip.com／Agoda／僅 Jalan）。
- **額度**：好材誌 routine 已於 2026-10-15 改為每日 2 篇。日本站 routine 建議與之錯開（例如每四小時一輪），不要兩邊同時每兩小時。
- **固定成本**：新網域一個；Cloudflare、Sanity 免費方案夠用；Claude 與 Ahrefs 訂閱是既有支出。
- **第一個 session 的順序**：(1) 建 repo 骨架，把好材誌的通用程式抽成模板；(2) 連 Ahrefs 後用 hub-keyword-planner 規劃 30 頁試點並出清單給 Darren 核准；(3) 改寫 Skill 來源規則；(4) Darren 建 Sanity 專案、Cloudflare 專案、網域後才部署；(5) routine 等建材站清單消化到一個段落再啟用。
